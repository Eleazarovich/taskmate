# Taskmate

### Pawn-to-King productivity for focused personal work

Taskmate is a chess-inspired personal Kanban board. Move tasks through a
fixed six-stage workflow—from **Pawn** to **King**—and make steady progress
visible, tactile, and rewarding.

> The workflow is Kanban. The experience is chess.

## About this project

Taskmate is an MVP for people who want a simple, motivating way to manage
their own work. It keeps the familiar structure of a Kanban board while
adding a lightweight game loop: every legal stage move changes a global
player rating, sound and motion provide feedback, and reaching **King**
triggers a victory moment.

The product is intentionally personal rather than collaborative. Users can
create independent boards for areas such as work, coding projects, personal
admin, or job searching. The six stages are fixed so the workflow stays
clear and consistent:

| Chess stage | Kanban meaning | Movement |
| --- | --- | --- |
| ♟ Pawn | Backlog | Starting point |
| ♞ Knight | To Do | Selected for work |
| ♝ Bishop | In Progress | Actively being worked on |
| ♜ Rook | Testing / Checking | Being verified |
| ♛ Queen | Review | Final polish or approval |
| ♚ King | Completed | Finished |

Tasks may move only one stage at a time. Forward movement earns one rating
point, backward movement removes one point without taking the rating below
zero, and invalid moves do not change the score.

## Highlights

- Personal accounts with cookie-based sessions and bearer-token support.
- Multiple independent Kanban boards.
- Task creation, editing, deletion, priorities, due dates, and free-form tags.
- Strict adjacent-stage movement from Pawn to King.
- Global rating with player statistics and recent movement history.
- Chess-inspired sounds, animations, and completion feedback.
- FastAPI and SQLAlchemy persistence with SQLite by default.
- OpenAPI documentation generated by the backend and maintained as a checked-in contract.

## Getting started

### Prerequisites

- Python 3.11 or newer
- [`uv`](https://docs.astral.sh/uv/)
- Node.js and npm

### 1. Start the backend

From the repository root:

```bash
make install
make run
```

The API starts at <http://localhost:8000>. FastAPI's interactive
documentation is available at <http://localhost:8000/docs>.

### 2. Start the frontend

Open a second terminal and run:

```bash
cd frontend
npm install
npm run dev
```

The web app starts at <http://localhost:4028>.

### Run as one container

The Docker image builds the frontend as a static export and serves it from
FastAPI alongside the API:

```bash
docker build -t taskmate .
docker run --rm -p 8000:8000 \
  -e TASKMATE_DATABASE_URL=sqlite:////data/taskmate.db \
  -v taskmate-data:/data \
  taskmate
```

Open <http://localhost:8000>. To use an API hosted at another origin, pass
`--build-arg NEXT_PUBLIC_API_URL=https://api.example.com` to `docker build`.

## Configuration

The application works locally without an environment file. Use these
variables when changing the default setup:

| Variable | Service | Default | Purpose |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | Frontend | `http://localhost:8000` | Backend URL used by the browser |
| `TASKMATE_DATABASE_URL` | Backend | `sqlite:///./taskmate.db` | Primary database URL |
| `DATABASE_URL` | Backend | — | Generic fallback database URL |
| `TASKMATE_CORS_ORIGINS` | Backend | Local frontend origins | Comma-separated allowed browser origins |

For example, to run the backend against a separate local SQLite file:

```bash
cd backend
TASKMATE_DATABASE_URL=sqlite:///./local.db uv run uvicorn main:app --reload
```

If the frontend is hosted on a different origin, set both
`NEXT_PUBLIC_API_URL` and `TASKMATE_CORS_ORIGINS` accordingly.

```bash
npm run build
npm run serve
```

## API and project structure

The backend exposes authentication, board, task, movement, and player
statistics endpoints. The API contract is defined in [`openapi.yaml`](openapi.yaml).

```text
.
├── backend/              FastAPI application, persistence, and tests
├── frontend/             Next.js application and UI components
├── openapi.yaml          Checked-in HTTP API contract
├── _docs/                Product and MVP documentation
├── Makefile              Common backend development commands
└── AGENTS.md             Repository-specific development instructions
```

The backend and frontend each retain their own README with more local
implementation detail:

- [`backend/README.md`](backend/README.md)
- [`frontend/README.md`](frontend/README.md)

2. Keep the API contract, backend models, and frontend types in sync.
3. Run the backend tests and the relevant frontend checks before opening a change.
